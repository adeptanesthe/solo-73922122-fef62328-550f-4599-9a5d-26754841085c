# 封口线候选决策树接管试算平台

封口线计划让**候选决策树**先接管一段连续整数温区。本平台用 Flask 提供网页，
支持录入原树、保存候选树与工况草稿、试算最长安全温区、确认接管方案，
并可输入读数查询实际使用的树与分拣类别。

## 一、数据约定

### 决策树（JSON）

- 叶子节点：`{"leaf": "类别名"}`，类别为非空字符串。
- 分支节点：

  ```json
  {"feature": "temperature", "threshold": 200, "left": {...}, "right": {...}}
  ```

  - `feature` 仅允许 `temperature`（温度）、`front`（前压）、`back`（后压）；
  - `threshold` 为 0..65535 的整数；读数 **≤ 阈值走 `left`，> 阈值走 `right`**；
  - 每棵树至多 **128 个叶子**，超出拒绝保存。

### 工况草稿（四个整数闭区间）

| 字段 | 含义 | 范围 |
| --- | --- | --- |
| `temperature` | 温度区间 | 0..65535 |
| `front` | 前压区间 | 0..65535 |
| `back` | 后压区间 | 0..65535 |
| `diff` | 后压−前压区间 | -65535..65535 |

区间均为 `[下限, 上限]`，下限不得大于上限；布尔值不被当作整数接受。

## 二、试算规则（不枚举读数组合）

在当前草稿上求**最长连续整数温区**，要求：

1. 温区内**每个温度**都存在合规压力组合（前压、后压在各自区间内，且
   后压−前压落在压差区间内）；
2. 对所有合规读数，原树与候选树判为**同一分拣类别**；
3. 多个等长温区时取**起点最低**者。

算法（见 `app/solver.py`、`app/tree.py`）：

1. 把两棵树展开为至多 128 个**轴对齐叶子盒子**（区间表示，非逐点枚举），
   分支按阈值切区间，空区间整枝剪枝；
2. 压差可行性用**闭式区间判据**：独立闭区间上 `back-front` 的取值范围为
   `[back_lo-front_hi, back_hi-front_lo]`，与压差区间判断相交即可，
   不需要枚举任何 `(front, back)` 组合；
3. 对两树**类别不同**的叶子盒子对，先与工况域求交裁剪，再判裁剪后的
   压力矩形是否满足压差约束，收集分歧温度区间并做区间合并；
4. 在工况温度区间上求补、合并，扫描最长连续整数段（平局取起点最低）。

复杂度上界为叶子对级别的区间运算 `O(128×128)` 加温度轴线性合并，
压力组合从不枚举；实测两棵 128 叶满树、满量程工况为毫秒级。

## 三、试算与确认的状态机

- 试算在**后台守护线程**执行，试算期间可以继续保存草稿，互不阻塞。
- 每次保存原树/草稿/确认都会使 `revision` 自增；每个试算任务绑定发起时的
  `revision` 与当时的树/草稿快照。
- 草稿一旦被修改（**即使改回原值**），旧试算立即标记为“已过期”，
  确认接口返回 409 并说明原因，必须用当前草稿重新试算。
- 只接受**当前草稿的成功试算**；试算无解、失败、进行中、过期均拒绝确认，
  响应中给出中文原因，并沿用当前分流（原树）。
- 确认后固化的是**确认时刻的候选树快照、工况与温区**；后续再改草稿不影响
  已确认方案。

## 四、确认后的分流规则

读数 `(temperature, front, back)` 仅在**同时**满足以下条件时使用候选树：

1. 温度落在已确认温区 `[zone_lo, zone_hi]` 内；
2. 前压、后压落在获准工况区间内；
3. `back - front` 落在获准压差区间内。

其余所有读数（温区外、任一压力不合规、压差不合规、无确认方案）一律使用原树。
查询接口会返回所用树、类别与逐条判定依据。

## 五、运行方式（Docker Compose）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

- 状态文件持久化在宿主机 `./data/state.json`（容器内 `/app/data`）。
- 停止：`docker compose down`（数据保留）。

本地无 Docker 时的等价运行方式：

```bash
pip install -r requirements.txt
SEAL_DATA_FILE=data/state.json python -m flask --app "app.web:create_app" run --port 8000
```

## 六、HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 操作页面 |
| GET | `/api/state` | 当前树、草稿、确认方案、revision、试算任务列表 |
| GET | `/api/examples` | 三组内置示例 |
| POST | `/api/original-tree` | 保存原树 `{"tree": ...}` |
| POST | `/api/draft` | 保存候选树与工况 `{"candidate_tree": ..., "draft": ...}` |
| POST | `/api/trials` | 发起后台试算，返回 `job_id` |
| GET | `/api/trials/<id>` | 查询试算状态/结果/是否过期 |
| POST | `/api/confirmations` | 确认 `{"trial_id": ...}`，失败返回 409 与原因 |
| POST | `/api/classify` | 读数查询 `{"temperature","front","back"}` |
| POST | `/api/rule-conversions` | 备用控制器规则转换（四个闭区间），返回规则/冲突/无解 |

## 六之二、备用控制器规则转换（不枚举真值或压力码组合）

备用控制器只能读到**完整 16 位温度**，前压、后压各取原读数的**高 8 位**作为
压力码（`code = value >> 8`，取值 0..255，每个码对应 256 个原值）。工艺员在
页面「⑦ 备用控制器规则转换」填写温度、前压、后压、实际压差四个整数闭区间，
点击“开始转换”，后端按**转换开始时生效的分流**（有确认方案且读数获准则候选树，
否则原树）给域内合规真值分类：

- **合规真值**：四个闭区间内、且后压−前压落在压差区间的整数读数。
- **冲突禁用下载**：若两组合规真值温度相同、前压码与后压码也相同，但分拣类别
  不同，备用控制器无法区分它们。响应与页面列出这两组（或多组）真值、压力码与
  类别，`download_allowed=false`，下载按钮禁用。
- **可下载**：工况内存在合规读数且无冲突时，返回 JSON 规则。每条规则含
  `category` 与四个整数闭区间：`temperature`、`front_code`、`back_code`、
  `code_diff`（= 后压码−前压码）。备用控制器的四项输入**全部**落入区间才命中。
- **无解**：工况压差本身不可行（不存在任何合规读数）时返回 `no_solution` 与
  中文原因，不提供下载。

正确性保证：

1. 每条规则只覆盖存在合规真值的码格，**无合规真值的输入不可能命中**；
2. 规则类别与该码格对应的**全部**合规真值一致（否则该格已判为冲突）。

算法（见 `app/converter.py`，全程区间运算，不枚举真值或压力码组合）：

1. 决策树展开为至多 128 个轴对齐叶子盒子，按工况域与确认获准盒子裁剪；
2. 压力轴按 256 宽码块切成至多一个“整码段”和两个边界“单码”：
   - 整码段上 `back-front` 的取值范围写成 `k=bc-fc` 的闭式整数不等式，
     与压差区间求交得到可行 `k` 区间；
   - 边界单码用裁剪后的具体原值区间做闭式判据并构造真值见证；
3. 冲突检测为码区之间的温度/前压码/后压码/`k` 区间求交，仅与叶子数和码段数
   有关（叶子对量级），128 叶满树、满量程转换为毫秒级。

## 七、内置示例（页面一键载入）

1. **可成功试算**：两树仅在高温高后压处分歧（原树 REJECT / 候选 REWORK），
   最长安全温区 `[150,200]`（51 个温度）。
2. **压差无解**：后压最大 120、前压最小 100，无法满足压差 `[100,200]`，
   无任何合规压力组合。
3. **无安全温区**：压力可行但两树在工况温区每个温度上都存在分歧读数。

规则转换示例（页面「⑦」内一键载入）：

1. **转换示例一（可下载）**：无确认方案、纯原树分流，阈值都在 256 码块边界上，
   转换成功并提供 JSON 规则下载。
2. **转换示例二（无解）**：压差闭区间与前/后压区间矛盾，无合规读数，返回原因。
3. **转换示例三（冲突禁用下载）**：页面自动完成 保存两树→试算→确认，再用放宽
   后的转换工况触发“同温度同两个压力码、类别不同”的冲突，列出真值并禁用下载。

## 八、自测

```bash
python -m unittest discover -s tests -v
```

- `tests/test_solver.py`：500 组随机小树与**全量枚举暴力法**逐例对照
  （暴力枚举仅存在于测试中）、128 叶满树 × 65535 满量程性能与边界、
  平局起点规则、压差裁剪、叶子盒子完备互斥抽查。
- `tests/test_converter.py`：规则转换对拍，300 余组随机小树（含/不含确认
  方案）与全量枚举神谕逐格核对“规则码格并集 == 合规真值码格集合、类别一致、
  冲突组数与见证一致”，并覆盖满量程性能与边界单码。
- `tests/test_rule_web.py`：转换接口端到端覆盖可下载、无解、确认后冲突禁用
  下载并列出真值、无原树拒绝、入参校验、转换无状态不改 revision。
- `tests/test_web.py`：端到端覆盖保存→试算→确认→分流、温区内外与
  压差/压力越界的用树选择、**旧试算过期与“改回原值仍被拒”**、
  试算中保存草稿、无解/失败拒绝确认、输入校验、重启持久化。

## 九、目录结构

```
app/
  tree.py        # 树校验、叶子盒子、分类路由
  solver.py      # 不枚举的区间求解器（试算最长安全温区）
  converter.py   # 备用控制器规则转换（码块区间运算，不枚举真值/码组合）
  validation.py  # 工况与读数校验
  store.py       # 线程安全 JSON 持久化 + 内存试算任务
  examples.py    # 内置示例（试算 + 规则转换）
  web.py         # Flask 路由
templates/ static/   # 网页
tests/               # 自测
Dockerfile docker-compose.yml requirements.txt
```
